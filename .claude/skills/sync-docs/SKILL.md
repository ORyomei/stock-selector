# ドキュメント同期チェック

コードが真実、ドキュメントは追従。実装を変えたら、その変更に言及している
ドキュメントを同じ作業の中で直す。「あとで直す」は禁止（このリポジトリの
README は src/scripts/ 時代の記述が残ったまま放置された前科がある）。

## 対象ドキュメント

| ファイル | 内容 | ズレやすいもの |
|---|---|---|
| `README.md` | 全体像・セットアップ・CLI例 | ディレクトリ構成、コマンド、既定値、ツール数 |
| `.github/copilot-instructions.md` | エージェント向け指示 | CLI コマンド一覧、ワークフロー |
| `docs/TRADING_SPEC.md` | 売買エンジン設計 | リスク管理ルール、クローズ条件 |
| `docs/ARCHITECTURE_REVIEW.md` | 構造レビュー | レイヤ構成、命名 |
| 各モジュールの docstring | 挙動説明 | パラメータ、戻り値、既定値 |

## 手順

1. **変更点の影響語を列挙する**
   変更したもの（関数名・CLI名・設定キー・既定値・パス・ツール名・件数）を
   キーワードにする。数値も対象（例: `max_hold_days` を変えたら `30日` も探す）。

2. **全ドキュメントを横断検索する**

   ```bash
   grep -rn "<キーワード>" README.md docs/ .github/ --include='*.md'
   ```

   ヒットした記述を実装と突き合わせる。判断基準は「今のコードを読んだ人が
   この文を書くか」。書かないなら直す。

3. **数え物は必ず数え直す**
   「9つのツール」「4戦略」「上限10」のような数字は、追加・削除のたびに腐る。
   出典のコード（`ALL_TOOLS`、`config/*.json` 等）から再カウントして合わせる。
   可能なら具体数をやめて「`agents/tools.py` の ALL_TOOLS を参照」に置き換える。

4. **既定値は config を正とする**
   `config/risk_limits.json` 等の実値とドキュメントの表を突き合わせる。
   ドキュメントに値を書く場合は「既定値。config で変更可能」と明記し、
   優先順位があるもの（例: timespan 別 max_hold_days がフォールバックより
   優先）はその順序まで書く。

5. **直せない・直さない場合は明示する**
   仕様が流動的で追従コストが高い箇所は、値を消して参照先だけ残すのも正。
   不整合を見つけたが本作業と無関係で大きい場合は、勝手に大改修せず
   ユーザーに報告して指示を仰ぐ。

## コミットへの含め方

- ドキュメント修正は**同じコミット**に含める（実装と別コミットにすると
  どちらかだけ revert されて再びズレる）
- コミットメッセージに書くのは変更理由。ドキュメント修正自体は本文に
  「README のツール数を更新」程度の一行で十分

## このリポジトリの既知の注意点

- README のアーキテクチャ図・ディレクトリ構成は `src/scripts/` 時代のもの
  からズレやすい。現構成は `src/{core,agents,cli,trading,infra,interfaces,web}`
- ツール数・ツール一覧は `src/agents/tools.py` の `ALL_TOOLS` / `AI_TOOLS` が唯一の真実
- CLI コマンドは `src/cli/app.py` の `@app.command` が唯一の真実
- リスク管理の値は `config/risk_limits.json` が唯一の真実。README の表は
  「デフォルト値」であり、timespan 別設定が優先されることを書き添える
