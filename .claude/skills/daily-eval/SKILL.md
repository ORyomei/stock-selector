# 日次評価 (daily-eval)

自動売買システムの1日を評価し、`diary/evals/YYYY-MM-DD_daily_eval.md` に記録する。
**前回の評価ファイルが基準値とウォッチ項目の唯一の引き継ぎ元**（チャット履歴に依存しない）。

## モード

- 引数なし → 「評価手順」を今すぐ実行
- 引数 `arm` → 「アーム手順」のみ実行（評価はしない）

## 評価手順

0. **前回評価の読み込み**: `diary/evals/` の最新ファイルを読み、基準値（総資産・累計%・
   確定成績・現金比率・保有銘柄）とウォッチ項目の状態を引き継ぐ。ディレクトリが無い/空なら
   「初回」として portfolio と logs から現状を基準に立てる。
   休場日（祝日・週末）だった場合はその旨を一行報告して終了してよい。

1. **本日の資産変化**: `uv run stock-selector portfolio status` と
   `logs/equity_history.jsonl` 末尾で総資産・現金・保有を確認。
   （`stock-selector macro` の出力は JSON が2個連結の場合があるので
   `json.JSONDecoder().raw_decode` で先頭のみパースする）

2. **指数比較**: 当日および稼働開始 2026-08-04 からの累計リターンを
   TOPIX (1306.T)・日経平均 (^N225) と比較。yfinance を使い、
   **中央値から3倍以上乖離した行は異常値として除外**（過去に +1051% 事故あり）。

3. **約定確認**: `diary/trades/` の当日分。
   **機械 stop_loss の初発動があれば必ず詳細報告**（最重要の未検証項目。
   AI が先回りして降りるため実射テストが済んでいない）。

4. **特筆すべき判断**: `diary/traces/` の当日分と daemon ログから 1〜3個。
   見送り根拠・反証ゲート却下・AI手仕舞い・deep_research / market_calendar の効き方など。

5. **ウォッチ項目の更新**（前回ファイルの表を引き継いで差分を書く）:
   - 回転の粗さ: 「買って数日で方針転換」の再発（既知: 7751 90分往復 / 4503 3日 / 2914 4日 −18,143）
   - ETF 退避パターン: 指数・高配当 ETF への退避比率
   - 反証ゲート却下頻度: 価格関係不正など同型エラーの再発（生成品質の定点観測）
   - イベント前の露出管理: market_calendar の直近イベントと現金比率の整合
   - 機械 stop_loss 未検証の解消有無
   - 状況に応じて項目の追加・解消も行う（解消したら ✅ を付けて次回から簡略化）

6. **レポート**: 以下の構成で簡潔に（長文にしない）。
   (a) 本日の損益 vs 指数（当日・累計の表）
   (b) 特筆すべき判断
   (c) ウォッチ項目の変化
   (d) 実力評価の一行更新
   大イベント（雇用統計・CPI・FOMC・日銀）を跨いだ直後はその影響評価も含める。
   末尾に「投資助言ではなく参考情報」の旨を添える。

7. **永続化**: レポート全文を `diary/evals/YYYY-MM-DD_daily_eval.md` に保存してから、
   ユーザーにも同じ内容を報告する。ファイル冒頭に機械可読の基準値ブロックを置く:

   ```markdown
   <!-- baseline
   date: YYYY-MM-DD
   equity_jpy: 3167772
   cum_pct: 5.59
   record: 14勝3敗
   realized_jpy: 173096
   cash_pct: 25.6
   holdings: 7267.T,9432.T,6503.T,6758.T,1489.T
   vs_nikkei_pt: +0.11
   vs_topix_pt: +1.08
   -->
   ```

## アーム手順（引数 `arm`）

1. `CronList` で既存の daily-eval 系ジョブを確認し、あれば `CronDelete` で削除（二重実行防止）
2. `CronCreate` で再作成:
   - cron: `11 16 * * 1-5`（平日 16:11 JST、大引け後）
   - recurring: true
   - prompt: `/daily-eval を実行してください。手順は .claude/skills/daily-eval/SKILL.md に従うこと（引数なしの評価モード）。`
3. ユーザーに伝える: ジョブID、**7日で自動失効するため失効予定日**、
   セッション限定（Claude Code 終了で消える）である旨、失効前に `/daily-eval arm` で再アームすること

## 備考

- 評価はシミュレーション（broker=simulator）の成績。投資助言ではない
- `diary/` は gitignore 済みなので評価ファイルはコミットされない
- セッション非依存の恒久運用にしたい場合は systemd timer 化を検討（未実装）
